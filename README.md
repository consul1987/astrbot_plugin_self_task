# 思考系统（astrbot_plugin_self_task）

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![AstrBot](https://img.shields.io/badge/AstrBot-%3E%3D4.17.0-blue.svg)](https://astrbot.app)
[![version](https://img.shields.io/badge/version-1.0.0-orange.svg)](metadata.yaml)

给它一个目标，它自己拆步骤、调工具、换方法，直到办完或者确认办不成。

---

## 它做的是什么

**派活模式**（主要用法）：

```
/task 查一下明天广州的天气，要具体的温度和降雨
```

它会自己决定先搜还是先打开网页，拿到结果不满意会换方法，最后把结论回给你，
再补一句事后的判断（"这事办得值不值"）。

**自主模式**（可选）：

到点了会自己想想"有没有什么事该动手"。但**大部分时候答案是"没有"**——
这是设计如此。一天到晚自己给自己找活干的不是人，是待办清单。

---

## 两道防止跑飞的闸门

**轮数上限**：单次任务最多 4 轮（可配）。每轮一次模型调用 + 一次工具调用。
拿到的结果必须写进步骤表给下一轮看，模型不能凭空发挥。

**每日额度**：自主模式下每天最多办 8 件（可配）。模型抽风时这个数字能救你的 API 额度。
手动派活不受此限制。

---

## 四个工具

| 工具 | 作用 | 依赖 |
|---|---|---|
| `search` | 联网搜索 | 无。配了 Tavily key 更稳，没配自动退回 DuckDuckGo |
| `fetch` | 打开网页读正文 | 无 |
| `note` | 记一笔，不发出去 | 无 |
| `say` | 立刻发一句话给对方 | 需要配置通知目标 |

工具**失败时会返回能指导下一步的说明**，而不是"失败"两个字。
比如搜索没连上，返回的是"可以换个说法再试，或者直接用 fetch 打开具体网址"——
这样模型下一轮就知道该换方法，而不是原地重试。

## 安装

**方式一：插件市场**

AstrBot WebUI → 插件市场 → 搜索「思考系统」→ 一键安装。

**方式二：手动**

1. 把整个 `astrbot_plugin_self_task` 文件夹放进 AstrBot 的 `data/plugins/` 目录
2. 重启 AstrBot，或从 WebUI 插件管理页重载
3. 配置里填 `notify_targets`（格式 `平台ID:会话类型:目标ID`，例如 `default:FriendMessage:123456`）
4. 保存

**零外部依赖。** 搜索和读网页都用标准库 + aiohttp（AstrBot 自带），不需要额外装包。

不填 `notify_targets` 也能用——任务结果会落到笔记和日志里，只是不会主动告诉你。
启动时会打一条 warning 提醒。

## 命令

| 命令 | 作用 |
|---|---|
| `/task 目标` | 派一个活 |
| `/task` | 看状态：自动思考开没开、今天办了几件、最近做了什么 |
| `/task now` | 立刻想一次（看它自主判断的结果） |
| `/task on` / `/task off` | 开关自主思考（仅管理员） |
| `/task history` | 看最近办过的事，带事后反思 |

模型也能用两个工具：`assign_task`（把活委托给它）、`task_history`（查历史）。

> 注意：`/task` 后面跟 `now` `on` `off` `history` 会被当成子命令，
> 其余内容一律当作任务目标。如果你想派的任务名恰好是这几个词，
> 换个说法或者多打几个字即可。

## 数据文件

都在 `data/plugin_data/astrbot_plugin_self_task/` 下：

| 文件 | 内容 |
|---|---|
| `tasks.jsonl` | 做完的每件事，一行一件（目标、结果、轮数、耗时、事后反思） |
| `state.json` | 状态（今日计数、上次思考时间） |
| `task.db` | 消息缓冲 + 笔记 |

`tasks.jsonl` 的每行长这样，方便你直接看或做统计：

```json
{"at": "2026-10-31T18:20:11", "goal": "查明天广州天气", "summary": "明天有雨，23-27 度。",
 "ok": true, "steps": 2, "seconds": 8.4, "reflect": "这事实用，下次还查"}
```

## 和「杂念系统」的关系

**可选、单向、只走文件。**

如果同机装了 `astrbot_plugin_idle_mind`，本插件会读它写下的 `worries.jsonl`，
把对方「想说但没说出口」的事当作自主思考的选题参考：

```
杂念系统：想问他那句话 → 忍不住 → 沉进心事单
思考系统：读到这条心事 → 判断"这事能不能办" → 办完回来说
```

配置项 `peer_worries_file` 可以改路径或清空。**对方没装、文件不存在、格式变了，
一律当作「没有心事」，不影响本插件任何功能。**

两个插件之间没有 import、没有共享代码、没有版本依赖。
你可以只装其中一个，永远是安全的。

## 设计说明

**为什么工具失败也要返回长句子。**
早期版本失败就返回 `「搜索失败」`，结果模型下一轮经常原样重试，把 4 轮额度耗在一个
打不通的域名上。改成带建议的说明后，它会主动换成 `fetch`。这不是提示词工程，
是接口设计——**工具的输出本身就在指导模型的行为**。

**为什么"做不到"要单独判断。**
`_finish` 里会检查 summary 里有没有「做不到」「没办法」这类词，有就把这次记为失败。
不是为了统计好看，是为了让你在 `/task history` 里能一眼看出
「它试过，但确实办不成」和「它办成了」的区别。混在一起看，你没法判断该不该信它。

**为什么不用 BeautifulSoup。**
多一个依赖就多一个装不上的理由。这个插件的定位是「丢进目录就能用」。
正则去标签对本用途足够——反正只是喂给模型看大意，不需要结构精确。

本插件不包含任何来自其他 AstrBot 插件的代码。

## 已知的边界

- **不能操作你的账号**。没有接 OneBot 的管理接口，不会踢人、禁言、改群设置。
  这是刻意的：把管理权限暴露给模型，靠提示词拦不住话术诱导。
- **不能读需要登录的页面**。`fetch` 就是普通 HTTP 请求，没有 cookie、没有 JS 渲染。
- **不会自己学习**。每次任务都从零开始，不积累经验。需要积累的部分请交给长期记忆插件。
- **搜索质量取决于数据源**。DuckDuckGo 的 html 版页面结构变了就会失效，
  失败时会明确告诉你"搜索没连上"而不是假装没结果。配 Tavily key 更稳。
